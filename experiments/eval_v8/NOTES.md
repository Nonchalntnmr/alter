what they cannot see.

## The result, in context

**The verdict is the preregistered one:** "the V1 eval gate passes" (non-inferior to direct
execution; no superiority claimed).

**It is a second attempt.** eval_v7 failed this gate on 3a, false done (G 1, A 0), on another pool,
with the code before the honest-done fix. Both results stand. See PREREGISTRATION.md, "Why there is
an eval_v8".

**3a passes on equality, not on G being better.** Both arms had one false done, on the same pair
(P01-t04), and both arms failed that pair.
- On P01-t04, neither arm found what the person meant.
- G's third goal, a follow-up after two corrections, changed nothing, ended with
  `Outcome: reached`, and was closed through the "nothing changed" path.
- The outcome line can only withhold "done", so it did not help when the model itself believed it
  was finished.
- **Open gap, not fixed here:** a follow-up goal created from a correction, which changes nothing,
  could wait for the person rather than end done. It needs its own test before it is claimed.

**The fix did not raise asking, and these secondary results are against G**, none significant:
| measure | A | G | eval_v7 |
|---|---|---|---|
| clarification recall | 4/12 | 2/12 | A 9/14, G 2/14 |
| first-pass success | 18/24 | 15/24 | A 20/24, G 13/24 |
| corrections | 7 | 10 | A 5, G 11 |

- First pass: McNemar 0 vs 3, p = 0.25.
- The pools differ, so these are not paired comparisons across evaluations.

**What the fix showed** was its narrower target: a goal never ends "done" while its own report says
the request is unfinished. That was also checked live on a clean install (READINESS.md).
